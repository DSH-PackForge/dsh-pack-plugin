## 对齐 spec r3：依赖内嵌（vendored）全面改造（2026-09-30）

主线：把依赖内嵌按 **manifest v5 r3 §2/§12** 与 **pack-structure v3 r3 §8** 重做。
**破坏性变更**：r2 形态的包（`vendored{}` 里用裸坐标键）从本版起**拒装**；`--prefer-offline` 语义被删除。

### ① 键语义（r3 §2）

- 直接依赖：`dependencies` 与 `vendored` 都用 **`vendor:<包名>`**；包名以 **tarball 内 `package.json`
  的 `name`** 为准（别名依赖也按真实名，并在 notes 提示核对 `bundles`）。值 = **包的精确版本**，
  不再是 commit sha —— 来源（`owner/repo#sha`）只留在随包 lockfile 的 importer `specifier` 里。
- 闭包条目：键 = **`name@version`** + `kind:"closure"` + `name` 必填（闭包上不记 `reason`）。
- **拒装**：`vendored` 里的裸键（r2 废弃形态）；`vendor:` 依赖缺 `vendored` 条目；同一包名两类并存；
  闭包条目无法在随包 `pnpm-lock.yaml` 的 `packages:`/`snapshots:` 里按 `name@version` 反查（防夹带）；
  阶段 0 还会核对 **tarball 内 name/version 与键、声明版本三处一致**。
- 导出侧新增：同一包名被内嵌两次（含跨 profile 的 npm/git 同名）→ **拒绝导出**并说明原因
  （键只带包名，装不下两个来源/版本；规范未定义此情形）。

### ② 安装端本地化（v3 §8.3 两支）

新增 `src/core/lockfile.js`，在 `pnpm install` 之前定点改写**落盘副本**的 `pnpm-lock.yaml`
（包内字节一个字不动，§8.6 第 6 条）：

| 支 | 触发 | 改动 |
|---|---|---|
| A · npm | lockfile 节点是 registry 版本 | importer `specifier`（`file:./x`）+ `version`（`file:x`）、`packages` 键、`resolution`（**现算 sha512 覆盖 integrity**）、`snapshots` 键，并补回节点 `version` 字段 |
| B · git | 节点含 `gitHosted` | **只改** `resolution.tarball`；`gitHosted`/键/`integrity` 全不动 |
| 闭包条目 | 在 `vendored{}` 里 | 只改该节点 `resolution.tarball` |

- 定位只能靠**包名**（git 节点的键版本段是 codeload URL，不是版本）；**同名多节点 → 拒装**，不猜。
- 执行改为 `pnpm install --frozen-lockfile --trust-lockfile`（coverage 完整时再加 `--offline`）；
  **删除 `--prefer-offline`**（它表达「本地优先、否则联网」，与 r3「来源由键唯一确定」矛盾）。
- frozen 失败时退一步 `--no-frozen-lockfile` 并在日志留痕（典型成因见 ③）。
- 无 lockfile 不再硬拒：方言包不需要它；非方言条目缺 lockfile 会明确告警并退化为 `file:` spec 安装。
- `vendor-blobs/` 落盘改为取**全部**计划条目——闭包条目不在 `dependencies` 里，此前根本不会落盘。
- Host 契约新增 `sha512`（base64，pnpm integrity payload）。

### ③ integrity 重算与 pnpm 11 冷静期

- 本地化时用**现算 sha512** 覆盖 lockfile 的 `integrity`（本地重打包后原值必然不符，不覆盖则拒装）。
- 新增 `src/core/pnpm-settings.js`：把随包 lockfile 的 `settings` **镜像**进包内 `pnpm-workspace.yaml`，
  并写 `minimumReleaseAge: 0`（只有 camelCase 有效；kebab 与 `--config.*` 都无效）。

### ④ 打包端义务

- **git 坐标优先内嵌 codeload 原件**（`fetchCodeloadTarball`）：原件与 lockfile 的 `integrity`
  逐字节相等，因此不需要重算、也不记 `reason`；取不到才回落 node_modules 重打包并记 `local-modified`。
- **上游探测三态**（`probeNpmUpstream`，§8.6.1）：200 → `exists`（不内嵌）；404/410 → `missing`
  （自动内嵌 + `upstream-missing`）；其余 → `unknown`（保守内嵌）。**挂在显式开关上，默认关闭**
  （理由见下"取舍"）。
- **离线可装性自检**（`coverageOfVendored`，§8.6.5 的等价静态校验）：导出即校验闭包是否收齐，
  不齐则带缺失清单告警。
- 体积阈值（>500MB 警告 / >2GiB 拒绝）沿用 `checkPackSize`，本版未改。
- 兼容 codeload 布局（`<repo>-<sha>/package.json`）与 `#path:` 子目录坐标；不兼容它，换成原件后
  阶段 0 会把自家 git 内嵌条目全判成「package.json 缺失」而拒装。

### 实测证据（本机 pnpm 11.7.0，均可复现）

1. **支 A 端到端**：真实包 `fflate@0.8.3` 从 node_modules 重打包（17 文件）→ lockfile 里 integrity
   **故意写错** → 本地化后 `pnpm install --frozen-lockfile --offline` **exit 0**、零网络装成。
2. **支 B 端到端**：codeload 形态归档（顶层 `<repo>-<sha>/`）只改 `resolution.tarball` →
   同样 frozen+offline **exit 0**；`resolution.tarball: file:<rel>`（不带 `./`）pnpm 接受。
3. **原件与 integrity 逐字节相等**：`https://codeload.github.com/swaylq/dsh-wildmon/tar.gz/<sha>`
   111,810 字节，sha512 与 DSH profile 里记录的 `integrity` 完全一致。
4. **pnpm 11 会校验 lockfile settings 与运行时配置**：不一致直接
   `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`（第一次跑支 B 就撞上）→ 这是 ③ 那条镜像规则的由来。
5. `minimumReleaseAge: 0` 写在 `pnpm-workspace.yaml`（camelCase）可让 pnpm 11 放行离线安装。

### 取舍与偏差（明确记录）

- **探测三态默认关闭**：规范 §8.6.1 要求打包端默认探测。0.3.5 曾把探测整个删掉——当时用带 `^`
  的范围版本拼 registry URL 导致全 404、把 8 个活着的依赖误判成「上游消失」。该 bug 现已由「读
  node_modules 实测版本折算精确版本」修掉，能力随之恢复；但默认联网探测会在断网时按
  `unknown` → 保守内嵌，把包吹大，所以本版把它做成显式开关（`opts.probeUpstream` / RPC
  `payload.probeUpstream`），默认仍是"不联网的手动 ∪ round-trip"。**要不要改为默认开，待定。**
- **④c 是等价静态校验，不是真的试装**：§8.6.5 原文是「以离线模式 dry-run 试装一次」；导出器跑在
  GUI 会话里、没有干净的试装环境，这里做同类的覆盖率校验（抓的正是"传递闭包遗漏"这一类缺陷）。
  真要试装，可在 CI 里对产出的 `.dspack` 跑一次 `installPack` 到临时 profilesRoot。

### 反馈给规范的缺口（实现时实测/推演出来，供 §8 与 §11 修订参考）

1. **`pnpm-lock.yaml` 不能算"可选"**：§3.1/§4 把它列为可选，但 §8.3 的本地化（认节点）、§12 的闭包
   防夹带、§8.6.3/§8.6.7 的 integrity 全都依赖它。带 `vendor/` 或闭包条目的包应改为**强制带 lockfile**，
   并定义缺失时的行为（本版选择"告警 + 退化为 file: spec 安装"）。
2. **`pnpm-workspace.yaml` 同理**：实测 pnpm 11 要求 lockfile 的 `settings` 与运行时配置一致，
   所以带 `vendor/` 的包还必须带能镜像这些 settings 的 `pnpm-workspace.yaml`（§8.6.8 只提了
   `minimumReleaseAge`，没提 settings 镜像）。
3. **git 节点的"版本"有两个**：lockfile 键的版本段是 codeload URL，节点内 `version:` 才是包版本。
   §12 说闭包键 `name@version` 的 version 取"lockfile 解析出的精确版本"——这里必须指明取哪个
   （取 URL 段才能过防夹带反查；取包版本会在反查时被误判夹带）。
4. **"按 tarball 内 `name@version` 在 lockfile 认节点"对 git 节点不成立**（键是 `name@<URL>`）；
   git 只能按包名找，因而**同名多 git 节点无法确定改哪个** → 建议规范写明"该包名在随包 lockfile
   里必须唯一，否则拒装"。
5. **`#path:` 子目录 git 坐标的内嵌语义未定义**：monorepo 根 `package.json` 与子包名不同，
   阶段 0 的 name 核对必须按 lockfile 的 `&path:` 下探（本版已实现），建议写进 §8.1/§8.3。
6. **往返导出（round-trip）义务未定义**：§8.1 要求"包内永远是来源风格"，但从**已安装 profile**
   再导出时，源状态里的 `package.json`/lockfile 已被本地化成 `file:`。好消息是信息没丢
   （importer 的 `specifier` 保留 git 形态；npm 节点本地化后 pnpm 会写回节点 `version` 字段），
   建议规范明确"导出端必须把它们反规范化回来源风格"，并规定安装端**不得删除节点 `version` 字段**。
7. **direct-mount 与层栈对账的冲突**：§8.3 要求直挂时把坐标从写入 profile 的 `package.json`
   剔除，而 §11.3.3 的 `reconcileProfile` 要求 "`bundles` 中同时是依赖的包必须存在 bundle 声明"
   ——剔除之后如何对账需要写明（DSHL 方言全走直挂，这条一定会在野外撞上）。
8. **r2 建议在文档里标"已废弃"**：现在 `protocol-2026-09` 标签里就是 r2，第三方照着标签实现
   不会知道它已被 r3 取代（v1 有"已废弃"标记，r2 没有）。

### 兼容与迁移

- 装了 r2 形态的包：本版**直接拒装**并给出可读原因（"裸键是已废弃的 r2 形态 → 请作者用 r3 重新导出"）。
- 老启动器读 r3 包：`vendor:` 键对 pnpm 是非法包名 → **响亮失败**（规范预期行为，见 v3 §8.5 兼容矩阵）。
- DSHL 方言（依赖**值** = `vendor:<file>.tgz` + `vendor/vendor.json`）继续"消费宽容、生产禁止"。

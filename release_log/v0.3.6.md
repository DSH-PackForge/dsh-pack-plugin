## 主线拆分离线包：只保留导入侧，导出侧移到分支（2026-09-30）

规范主干 `36e0405 specs: 主干收敛为基线 + dshVersions/launchers（vendoring 移至分支）` 之后，
`specs/` 里 `vendor/`、`vendored`、`离线` 零命中。主线据此把依赖内嵌**拆成两半**：

- **导出侧（产包）整族删除** —— 主线为减少 bug 不再提供这条路径（它在 0.3.5 之前出过
  「范围版本被当成版本 → 上游全被误判消失」的事故，见 `release_log/v0.3.5.md`）；
- **导入侧（装包）保留** —— 那条分支产出的、带 `vendor/` 的包，主线仍要能装；
- **展示侧保留** —— 市场详情页照旧显示「内嵌 N 个依赖」徽标。

完整实现（含导出侧）在 **`feat/vendoring` 分支**（从 `0df9559` 分出，已推送）。

| `src/core/workspace.js` | `.dshpkcfg` 白名单里的 `vendor` |

| `src/core/vendored.js` | 导出侧一半：`listProfileDependencies` / `collectVendoredForExport` / `expandVendorSelection` / `repackageFromNodeModules` / `repackageFromPnpmStore` / `fetchRegistryTarball` / `fetchCodeloadTarball` / `codeloadUrl` / `probeNpmUpstream` / `coverageOfVendored` / `coordFromDirName` |
| 测试 | `vendored-packer-r3.test.js`、`pnpm-settings.test.js`、`pack-home-vendor-r3.test.js`（及其对应用例） |

### 导入侧：保留（语义未改）

- `src/core/vendored.js` 消费侧：阶段 0 预检（依赖键对账、逐 tarball `sha256`+`size`、
  未登记/非 `.tgz`/缺件拒装、闭包条目按 `name@version` 反查随包 lockfile 防夹带、
  tarball 内 `name`/`version` 与键和声明版本三处一致）、DSHL 方言直挂、`vendor-blobs/` 落盘、
  覆盖判定（版本敏感）。
- `src/core/lockfile.js`：`pnpm-lock.yaml` 本地化两支（npm 四处同步 `file:` / git 只改
  `resolution.tarball`）+ 闭包条目只改 `resolution.tarball`；目标形态由真 pnpm 11.7.0 实测确定。
- `src/core/install.js`：阶段 0 → tarball 落盘 → lockfile 本地化 → `pnpm install
  --frozen-lockfile --trust-lockfile`（覆盖完整时再加 `--offline`）；方言直挂。
- `src/core/manifest.js`：`vendored{}` 结构校验与三处一致（消费必需）。
- `src/core/host.js` / `host-node.js`：`sha512`（本地化覆盖 integrity 用）。
- 展示侧：`src/core/market.js` 的 `vendored` 透传与 `r2Badges` 徽标、`src/settings.js` 的
  `market.r2.vendored` / `market.r2.none` 文案。

### 版本

`smoother-deepseek-harness` 两个 profile 里装着的就是 0.3.5 —— 同一个版本号不宜再承载不同内容。

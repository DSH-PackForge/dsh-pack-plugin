## 宿主侧打包为自包含 bundle，修复「自动重启失效」与「切换后 failed to import」（2026-09-27）

宿主入口从 `src/index.js` 切到 `lib/host.js`：`scripts/bundle-host.mjs` 用 esbuild 把 `fflate` / `proxy-agent` / `proxy-from-env` 及其传递依赖全部内联成单文件，迁装管理器不再需要手工同步「顶层 node_modules 依赖清单」。这同时修了两个此前埋下的问题：

- `import.meta.url` 从 `src/` 变成 `lib/` 后，migrate-helper 与进度窗资源（progress-main.cjs / progress-window.ps1 / progress.html）路径解析错位，导致**切换 profile 自动重启失效、一直显示「切换中」**；现在这些资源由打包脚本一并产出到 `lib/`。
- 之前 `MANAGER_DEPS` 清单在引入 proxy-agent 后漏更，导致**切换 profile 迁装后 failed to import**；现在管理器自包含，清单整个删掉。

## 修复热重载后「整合包」设置入口消失（2026-09-27）

设置里把「整合包」插件关→开（或安装其它插件触发宿主重载）后，设置页的「整合包」入口会莫名消失、且无任何报错，只能重启恢复。根因是 DSH 的 locale 服务**全局去重**：`locale.register` 对同一 namespace+locale 重复注册会抛错，而旧注册不随插件 fiber 卸载清理；重载时这行抛错把后面的 `settings.section` 注册整个中断。

修复：重复注册（`already has locale`）安全忽略。顺带把 `settings.section` 注册改为幂等闸门（`section-gate`，dsh-market 同款），并补上设置页导航图标（folder-zip logo，经 MutationObserver + CSS mask 认领本插件的导航行）。

## 宿主插件加载健壮性（2026-09-27）

- **skill 读取容错**：单个 skill 的 `SKILL.md` 缺失 / 半写 / 损坏时只降级为「跳过该 skill」，不再因模块顶层 import 抛错而让整个宿主插件（含 RPC、安装、profile 等与 skill 无关的能力）一起 failed to import——例如 `.dspack`/pnpm 安装中途正在重写插件目录、文件尚未落盘时恰好被宿主 import。
- **安装源归一化**：剥离粘贴路径首尾空白与成对引号，修 Windows「复制路径」给带空格 / 中文路径套双引号导致的「找不到整合包文件」。
- **`sessions.create` 返回值形状修正**：按真实实现（直接返回 sessionId 字符串）处理，`发送到聊天` 新建会话不再误判失败。

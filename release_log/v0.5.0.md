## 取消离线包（vendored）支持，回到规范基线（2026-09-30）

规范主干提交 `36e0405 specs: 主干收敛为基线 + dshVersions/launchers（vendoring 移至分支）` 之后，
`specs/manifest/v5.md` 与 `specs/pack-structure/v3.md` 里 **`vendor/`、`vendored`、`离线` 零命中**：
顶点收敛为「基线 + `dshVersions` + `launchers`」，依赖内嵌整族移到分支。本插件同步拆除，回到纯基线。
**破坏性变更**（0.4.0 的 r3 内嵌能力不再存在），故版本按 0.x 语义走 minor：`0.4.0 → 0.5.0`。

### 保留（未被牵连）

- 容器与形态：`.dspack` v3、`overrides/`、`home/`、`files[]` 指针下载、profile / dshhome 两形态。
- 兼容性字段：`dshVersions`（交集决策）、`launchers`（六行判定表 + 警告放行留痕）、launcher 注册表端点、市场徽标。
- 其它既有能力：悬浮球入口、多 profile junction 切换、任务中心、市场浏览、`.dshpkcfg`。

### 行为影响（对装了旧包的场景）

- 带 `vendor:` 键的包：键会原样进重建的 `package.json` → pnpm 报**非法依赖名**（响亮失败，不会静默装错）。
- 带 `vendored{}` 字段的包：按**未知字段忽略**（规范的前向兼容规则：消费者必须忽略不认识的字段），
  安装不再做任何内嵌相关校验或落盘；`vendor/` 目录里未被 `overrides/` 引用的文件不会落盘。

### 历史保留（未重写）

`0.4.0` 的 r3 实现（键语义、lockfile 本地化两支、codeload 原件、探测三态、离线自检与实测证据）
**完整留在 git 历史与本仓库 `release_log/v0.4.0.md` 里**，没有 revert、没有删提交。
若规范的 vendoring 分支日后要合并回主干，可从 `0.4.0`（提交 `0df9559` 一带）取回该族实现；
`release_log/v0.4.0.md` 里那份「反馈给规范的 8 条缺口」也仍然有效。

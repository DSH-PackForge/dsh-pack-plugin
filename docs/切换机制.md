# 多 profile 切换机制（junction 换指 + 脱管首次迁移）

DSH 官方桌面写死启动 `profiles/desktop`（`apps/desktop/src/paths.ts`，无 env 覆盖）。本插件不碰官方源码，靠「改目录身份」实现切换。

## 核心：desktop 做成 junction

```
profiles/
  default/          ← 原 desktop 真实目录（首次迁移时改名保留）
  codex/            ← 真实 profile（各自占一个目录）
  pokemon/
  desktop   ->  junction  → 指向「当前激活」的那个真实 profile
```

- **切换 = 删旧 junction + 建新 junction**（`unlink` + `symlink`，`src/junction.js`）。
- 删除 junction 必须用 `unlink`（lstat 语义）。红线：**绝不用 `rm -r`**——Windows 会递归删掉 junction 目标目录的内容。

## 两条路径

### 稳态切换（desktop 已是 junction）
inline 完成，不碰目标目录句柄 → 无 EBUSY、无需退出桌面。

### 首次迁移（desktop 还是真实目录）—— 必 EBUSY
必须先把真实 `desktop` 改名成 `default`。运行中的宿主进程持有 `profiles/desktop/` 内文件句柄（node_modules、watcher、日志），`fsp.rename`（`MoveFileEx`）会返回 `EBUSY: resource busy or locked`。**这一步无法在线完成**，流程交给脱管进程：

```
点「切换」→ 宿主检测 EBUSY → 派生脱管迁移进程（与宿主进程树脱钩）
  1. 杀 electron 主进程树（taskkill /F /T）释放锁
  2. 轮询 rename(desktop → default) 直到成功
  3. 建 junction(desktop → target)
  4. 落 state（activeProfile=target, desktopIsJunction=true）
  5. 重新拉起桌面（复用主进程原命令行）
  6. 退出
```

用户无感，只看到一次自动重启。

## 脱管进程实现要点

- 用 `process.execPath`（= electron.exe）+ 环境变量 `ELECTRON_RUN_AS_NODE=1` 当纯 node 跑 helper，不依赖 PATH 上的 node（安装环境里 node 不一定在 PATH，但 electron 一定在）。
- 宿主进程的 `process.ppid` = electron 主进程 PID（进程树：electron main → dsh-desktop-host → 插件），杀它就杀整棵树；helper 因 `detached:true` 不在该树里，存活。
- `detached: true + stdio: 'ignore' + unref()`，否则随宿主一起死。

## 其它已确证事实

- profile 只在启动时读一次 → **任何切换都需重启才生效**，零改动下无法消除。
- skills 在 home 级 `$DSH_HOME/skills`，不在 profile 目录内 → 换 profile 必须单独换 skills（`junction.js` 的 `swapHomeSkills`，只动带 skills 的目标，不碰用户 home 级 skills）。
- dev 沙盒：`$DSH_HOME` = `apps/desktop/.desktop-build/development/home`；state 文件 = `<home>/dsh-packforge.json`。

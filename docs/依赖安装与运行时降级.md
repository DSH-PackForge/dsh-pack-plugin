# 改动报告（安装依赖复用 DSH 自带运行时 + 降级）

> 记录 2026-09-27 本轮对 `@dsh-packforge/dsh-pack-plugin` 的改动。原则不变：**零官方源码改动**（DSH 外壳零改动）。

## 概述

安装 `.dspack` 时 `pnpmInstall` 原先直接 `host.exec('pnpm', ['install', ...])`，**依赖用户机器 PATH 上的 pnpm + node**。没装 node/pnpm 的用户装整合包会直接失败。

DSH 桌面版（Electron）本身就内置了运行时（`resources/runtime/`，pnpm 11.7.0 + node 24.21.0），DSH 自己跑 pnpm 的方式是 `ELECTRON_RUN_AS_NODE=1 "<desktop.exe>" .../runtime/pnpm/bin/pnpm.mjs`。本轮改为**复用这套自带运行时**，仅在非桌面环境（CLI / 测试 / 旧版 DSH）下回退 PATH 上的 `pnpm`。

## 1. 入口解析（`src/host-node.js`）

导出纯函数 `resolvePnpmEntry({ env = process.env, resourcesPath = process.resourcesPath })`：

1. `DSH_DESKTOP_PNPM_ENTRY` 环境变量非空 → 直接返回（最高优先级，与 DSH 自身的覆盖入口一致）。
2. 否则 `path.join(resourcesPath, 'runtime', 'pnpm', 'bin', 'pnpm.mjs')`。
3. 都没有 → `null`（回退 PATH）。

## 2. `pnpm()` 与共享 spawn（`src/host-node.js`）

- 新增 `pnpm(args, opts)`：找到自带入口且文件存在时，用 `process.execPath`（桌面端可执行文件，即 electron）+ `ELECTRON_RUN_AS_NODE=1` 以纯 node 模式跑 `pnpm.mjs`；否则回退 `pnpm`（PATH）。
- `exec` 与 `pnpm` 共用 `#spawnRun`（异步 spawn + 可选 onOutput 流式捕获 + `timeoutMs` 超时杀进程树），返回值从 `{ status, error }` 扩展为 `{ status, error, timedOut }`。
- `#applyProxyEnv(env)`：显式代理地址 → 覆盖 `HTTP_PROXY`/`HTTPS_PROXY`（大小写）；`direct` → 清除代理变量强制直连；两者皆无 → 保留继承。**对「自带 pnpm」与「PATH pnpm」两条路径一致生效**（先构造一次带代理的 `baseEnv`，两条路径各自补充）。

## 3. 降级策略

| 层级 | 触发条件 | 动作 |
|---|---|---|
| ① env 覆盖 | `DSH_DESKTOP_PNPM_ENTRY` 非空 | 直接用它 |
| ② 自带运行时 | `resources/runtime/pnpm/bin/pnpm.mjs` 存在 | `process.execPath` + `ELECTRON_RUN_AS_NODE=1` |
| ③ 启动失败回退 | 自带 pnpm 存在但 **spawn 失败**（`status === null && !timedOut`） | 回退 PATH `pnpm` |
| ④ 无自带运行时 | 前两者都没有 | PATH `pnpm` |

关键判定：**只在 `status === null` 且非超时**时回退。pnpm 已运行但退出码非 0（真实安装失败：依赖冲突 / registry 认证等）**不**换版本重跑——否则会二次报错，或让 10 分钟超时翻倍成 20 分钟。

另有独立一层（`src/core/install.js`）：`--frozen-lockfile` 失败会自动去 frozen 重试一次。

## 4. Host 接口（`src/core/host.js`）

`Host` 接口新增 `pnpm(args, opts)` 文档方法，默认退化为 `exec('pnpm', ...)`；`src/core/install.js` 的 `pnpmInstall` 优先调 `host.pnpm`（无则退回 `host.exec('pnpm', ...)`），core 层保持 host 无关。

## 涉及文件清单

| 文件 | 改动 |
|---|---|
| `src/host-node.js` | `resolvePnpmEntry` / `pnpm()` / `#applyProxyEnv` / `#spawnRun`（含 `timedOut`） |
| `src/core/host.js` | `Host` 接口补 `pnpm()` 文档方法 |
| `src/core/install.js` | `pnpmInstall` 改用 `host.pnpm` |
| `test/host-node.test.js` | `resolvePnpmEntry` 3 条 + `pnpm` 1 条 |

## 测试

- `resolvePnpmEntry`：env 覆盖优先 / resourcesPath 标准布局 / 两者皆无回退 `null`。
- `pnpm`：用 env 覆盖 spawn 假 `pnpm.mjs`，断言 argv、`ELECTRON_RUN_AS_NODE=1`、代理透传。
- 全量 `pnpm test`：43/43 通过。
- 实机验证：`ELECTRON_RUN_AS_NODE=1 "DeepSeek Harness.exe" .../pnpm.mjs --version` → `11.7.0`。

## 遗留说明

- 第 ③ 层（spawn 失败回退）未做 hermetic 单测：触发它需要让 `process.execPath` 本身的 spawn 失败，单测环境里做不到（execPath 恒为有效 node）。逻辑简单、可 review，暂以代码评审 + 前两层测试覆盖代替。
- 自带运行时的 pnpm 版本随 DSH 升级变化：若未来 DSH 换用 pnpm 12（shim + 原生 `@pnpm/exe.*` optionalDeps）或锁文件版本不匹配，`--frozen-lockfile` 失败会去 frozen 重试一层兜底；但「版本不兼容」不在第 ③ 层回退范围（那是退出码非 0 的真实失败）。
- 本报告只覆盖安装路径的 pnpm 调用；`ensure-manager.js` 拉管理器走 `host.download`（直接下载 tarball，不经过 pnpm），`migrate-helper.js` 的 `pnpm start:desktop` 仅限开发沙箱（`detectDevRepoRoot`），均不受影响。

# 任务中心（非阻塞安装 / 导出 / 建库 + 独立进度小窗）

## 背景

安装 / 导出原本在设置面板内 inline 执行：宿主跑 `pnpm install`、git 打包时，UI 阻塞等结果；一旦关闭设置面板，进度与进程输出就丢了，用户只能干等或盲猜。

目标：把「重操作」从设置面板里解耦出来 —— 端点立即返回 `taskId`，真正的活儿放到独立 Electron 窗口「任务中心」里跑，关面板不丢进度，且能看到阶段时间线与 stdout/stderr。

## 设计：内存注册表 + 快照文件跨进程

任务中心是独立窗口（独立 renderer 进程），宿主进程内跑着真正的任务。两边不建长连接，而是：

- **宿主进程**：内存 `Map<id, task>`（`src/tasks.js`）是唯一事实源；每次变更把全量快照写进 `os.tmpdir()/dsh-pack-tasks-<home>.json`（100ms 节流）。
- **小窗进程**：每 200ms `readFileSync` 读快照渲染（`src/task-center.html`），读不到就显示空。
- 快照只做**跨进程搬运**，不是持久化 —— 宿主退出即失效；小窗靠快照里的 `hostPid` 探测宿主是否还活着，宿主没了自动关闭。

关键点：小窗不 push、宿主不 pull，都是「宿主写、小窗读」的单一方向，无锁、无孤儿连接、无 IPC 协议要维护。

## 任务生命周期

```
端点 ──> createTask({kind, title, home}) ──> enqueue(job)
                                             │
                                             ▼
全局串行队列（queueTail.then(job)，失败不断链）
                                             │
                 progressBridge(id)  ·  logSink(id)  ·  finish(id, {ok})
                          │                    │                │
                          ▼                    ▼                ▼
                  阶段 timeline 推进      stdout/stderr 分行缓冲   状态 → done/failed
```

- `enqueue`：`queueTail = queueTail.then(job).catch(()=>{})` —— 全局串行，前一个 settle（无论成败）才跑下一个。
- `progressBridge(id)`：`(stage, detail)` 推进阶段为 running + 更新 label + 记录 current；未知阶段静默忽略，已 done 的阶段不回退。
- `logSink(id)`：按 `\n` 切行、去 `\r`、半行缓存在 `_pending`（`finish` 时强刷）；上限 1000 行 / 256KB，超限丢最旧并置 `logTruncated`。
- `finish(id, {ok})`：ok → 全阶段 done；fail → current 标 failed、其余 running 标 done。

## 阶段定义（`STAGE_DEFS`，`src/tasks.js`）

| kind | 阶段 |
|------|------|
| install | download / extract / install / files |
| export | scan / manifest / collect / pack / write |
| create | init / manager |

## 子进程输出捕获

`src/host-node.js` 的 `exec` 加可选捕获：`opts.onOutput` 存在时 `stdio: ['ignore','pipe','pipe']`，stdout/stderr 的 data 都喂给 `onOutput`（不改变原有 inherit 行为）。`install`（pnpm）与 `export`（git）把 `onOutput` 一路透传进 core 的 exec 调用，输出进任务日志。

## 端点

- `pack/install`、`pack/export`、`profile/create`：非阻塞，立即返回 `{taskId}`。
- `task/list`、`task/get`：列表 / 查询任务（公开视图，剥掉内部字段）。
- `task/window-open`：打开（或聚焦）任务中心小窗。

前端（`src/settings.js`）`watch(id)` 每 600ms poll `task/get`，done/failed 时停轮询并刷新列表（failed 弹错误）。

## 小窗

- `src/task-center-main.cjs`：frameless、always-on-top、`nodeIntegration:true` 的独立窗口；ready-to-show 时把自己的 pid 写进 marker 文件（单实例判定），closed 时清掉。
- `src/task-center.html`：深色 renderer，标题栏 `-webkit-app-region: drag`；任务卡 = 标题 + 状态徽章 + 阶段时间线圆点 + 可折叠 `<details>` 日志（展开时自动滚到底）。

## 空整合包：自带管理器基线

「空整合包」不是真的空 —— 它必须含管理器插件基线，否则：

1. profile 里没有 `@dsh-packforge/dsh-pack-plugin` → 切换过去就是「单程票」，切不回来。
2. `switch` 读 `package.json`，没有就抛 ENOENT。

`profile/create` 因此：写最小 `package.json`（`dsh.profile.bundles: []`）+ 从激活 profile 迁装管理器与 `fflate` 到新 profile（`ensureManagerInProfile`，复制 `node_modules` 并登记进 `package.json` 的 `dependencies`）。

这一步也并入任务中心：`profile/create` 立即返回 `taskId`，建目录 / 写 package.json / 迁装管理器作为一个 `create` 任务（`init` → `manager`）跑。重名预检留在同步层（立即报错，不建任务）；任务内失败清掉半成品目录，不留残废 profile。

## 红线 / 坑

- 快照是**搬运不是持久化**：宿主退出后任务即失效，不要把任务中心小窗当历史记录源。
- 小窗 spawn 用 `process.execPath`（= electron.exe）+ 删 `ELECTRON_RUN_AS_NODE`，保证用同一个 electron 跑起来（`src/tasks.js` `spawnWindow`）。
- 曾出现 `tasks.create`（不存在）typo，运行时 `pack/install`/`pack/export` 会 `TypeError` —— 已修为 `tasks.createTask`。端点层目前没有单测，这类错 `node --test` 抓不到。
- 管理器迁移是本地 `fsp.cp`，无子进程 → `create` 任务没有进程输出日志，只有阶段时间线 + 状态徽章。

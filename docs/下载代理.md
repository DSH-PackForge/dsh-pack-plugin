# 改动报告（下载代理支持）

> 记录 2026-09-26 本轮对 `@dsh-packforge/dsh-pack-plugin` 的改动。原则不变：**零官方源码改动**（DSH 外壳零改动）。

## 概述

市场索引、包详情、`.dspack`/`.tgz` 安装、npm registry 拉取此前全部**直连**（`NodeHost.download` 只用 `http.get`/`https.get`，不认代理），连不上 GitHub Pages / GitHub release 的机器（典型：无梯子环境）会直接超时失败。

本轮给下载通路加了代理支持，三层来源，**显式设置项 > 环境变量 > Windows 系统代理**：

1. **设置项**（`config.proxy`）：About 页「网络」区块三档选择——`自动`（空值，回落下方两级）/ `直连`（`'direct'`，跳过一切代理）/ `手动`（代理地址），保存即生效（无需重启）。
2. **环境变量回落**：`HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`（含大小写变体）。
3. **Windows 系统代理回落**：无显式配置、无环境变量时读 WinINET 注册表（`ProxyEnable` + `ProxyServer` + `ProxyOverride` 旁路），覆盖 Clash / V2Ray 的「系统代理」模式。

支持的代理协议：`http` / `https` / `socks` / `socks4` / `socks5` / `pac`（由 `proxy-agent` 按协议自动分发到对应的 `http-proxy-agent` / `https-proxy-agent` / `socks-proxy-agent` / `pac-proxy-agent`）。

---

## 1. 下载核心（`src/host-node.js`）

- 新增依赖：`proxy-agent@8`（协议分发 + 代理 agent 实现）、`proxy-from-env`（标准环境变量解析，含 `NO_PROXY` 匹配）。
- `NodeHost` 新增私有字段 `#proxyUrl`（显式配置）、`#proxyAgent`（缓存的 agent，记录其 proxy URL，变更即重建）、`#sysProxy`（系统代理缓存）。
- 新增公开方法 `setProxy(url)`：设置显式代理，空值清除、回落环境变量/系统代理。
- 新增私有方法 `#agentFor(url)`：按「显式 > 环境变量 > 系统代理」解析，均无返回 `null`（保持原直连行为）。
- `#downloadOnce` 里在 `options` 上挂 `agent`：

  ```js
  const agent = this.#agentFor(u);
  if (agent) options.agent = agent;
  ```

- 关键坑（已踩）：`proxy-agent@8` 的 `ProxyAgent` **不再接受 URL 字符串入参**，必须用 `getProxyForUrl` 回调固定返回代理地址：

  ```js
  new ProxyAgent({ getProxyForUrl: () => proxy }) // 正确
  new ProxyAgent(proxy)                          // v8 下被当 options 对象，静默直连
  ```

- 与既有机制的兼容：重定向每一跳重新 `#downloadOnce`（各自按新 URL 重新选代理）；`extraCa`（Windows 系统根 CA 回退）与 `agent` 互不冲突，`ca` 由 agent 透传给 CONNECT/TLS。

### 1.1 Windows 系统代理自动检测

- 无显式配置、无环境变量时回退读 WinINET 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`：`ProxyEnable` 为 0 视为未启用；`ProxyServer` 支持单条裸 `host:port`（所有协议共用）或 `proto=host:port` 分号列表（如 `http=...;https=...`）。
- `ProxyOverride` 旁路：回环地址（`localhost` / `127.0.0.1` / `::1`）**恒直连**；`<local>` 匹配无点主机名；其余按精确或 `*` 通配匹配（如 `127.*`、`192.168.*`）。不读 `AutoConfigURL`（PAC 脚本）。
- 缓存一次；瞬时下载失败重试前清缓存重新探测（用户刚开关代理，下一次重试能接住）。

## 2. 配置接线

- `src/index.js` `apply()`：启动时异步读 `dsh-packforge.json` 的 `config.proxy` 并 `getHost().setProxy(...)`（读不到/异常不阻塞启动）。
- `src/endpoints.js` `config/set`：保存配置后立刻 `getHost().setProxy(s.config.proxy)`，代理立即生效无需重启。`config/get` 原样返回 `config`，UI 挂载时回填。`config.proxy` 取值：空 = 自动、`'direct'` = 强制直连、其余 = 代理地址。
- **持久化**：`config.proxy` 经 `writeState` 落盘 `$DSH_HOME/dsh-packforge.json`（JSON，2 空格缩进），跨重启保留；启动时 `apply()` 读回并 `setProxy`。环境变量 / Windows 系统代理不归插件持久化，由系统与代理客户端（Clash）管理——「自动」模式每次下载重新探测，天然跟随。

## 3. UI（`src/settings.js`，已重新打包 `lib/client.js`）

- 挂载时 `config/get` 回填当前设置；保存走 `config/set`，成功提示「已保存代理设置（立即生效）」。
- 新增双语文案：`group.network`、`field.proxyMode`、`proxyMode.*`、`field.proxy`、`hint.proxy`、`result.proxySaved`。

## 遗留说明

- **PAC 不支持**：`AutoConfigURL`（自动配置脚本）未解析，仅 `ProxyServer`（手动代理）。需要 PAC 时得走 Electron `session.resolveProxy`（桌面端专属）。
- 系统代理路径未做 hermetic 单测（读注册表 + `spawnSync('reg')`，依赖真实环境），以本机端到端验证代替；如需单测，可把注册表读取抽成可注入的 `readWinProxy()`。
- 显式配置的代理对**所有** URL（含 `localhost`/内网）生效，不做 `NO_PROXY` 白名单——符合「显式配置即用户意图」；若需内网绕过，可在 `#agentFor` 里给显式代理也套一层 `NO_PROXY`。
- 环境变量路径的 `NO_PROXY` 匹配委托给 `proxy-from-env`，未单测该路径（只测了显式 `setProxy` 通路）。

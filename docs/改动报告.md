# 改动报告（创建/导入弹窗 · 保留名拦截 · 图标）

> 记录 2026-09-25 本轮对 `@dsh-packforge/dsh-pack-plugin` 的改动。原则不变：**零官方源码改动**（DSH 外壳零改动）。

## 概述

围绕「管理页 → 创建整合包」区块，做了三件事：

1. **创建/导入弹窗**：点「创建空的整合包」弹窗输名字（kebab-case 校验）、点「导入新包」弹窗收集 `.dspack` 路径。
2. **保留名拦截**：禁止把 `desktop` / `default` 当 profile 名新建。
3. **图标**：插件管理页图标换成自定义 zip 图标；设置面板左侧齿轮经查证**插件侧无法更换**，维持原样。

---

## 1. 创建/导入弹窗

原来「创建空的整合包」「导入新包」两个按钮直接触发操作，没有输入环节。现在都改成先弹窗、校验通过才提交。

- 实现位置：`src/settings.js`
  - `openDialog(type)` / `closeDialog()` —— 打开/关闭弹窗，重置 `fieldError`、`submitting`
  - `doCreate()` / `doImport()` —— 校验链 → `call('profile/create')` / `call('pack/install')`
  - `renderDialog()` —— 模态层：输入框（`autoFocus`）、回车提交、内联错误、取消按钮 + 点遮罩关闭

- 校验链（`doCreate`）：
  1. 空名字 → `err.name`
  2. 不合 kebab-case → `err.nameInvalid`
  3. 命中保留名 → `err.nameReserved`（替换 `{name}` 占位符）
  4. 提交后后端再校验一次（双重校验），失败把后端错误回填到弹窗内联

- 新增文案（`src/settings.js` 的 zh / en 双语言表）：
  `err.nameInvalid`、`err.nameReserved`、`hint.nameFormat`、`hint.import`、`dialog.createTitle`、`dialog.importTitle`

## 2. 保留名拦截（desktop / default）

- 共享契约常量 `src/channel.js`：
  ```js
  export const PROFILE_NAME_RE = /^[a-z0-9]+(-[a-z0-9]+)*$/;
  export const RESERVED_PROFILE_NAMES = ['desktop', 'default'];
  ```
- 后端双重拦截：
  - `src/endpoints.js` —— `profile/create` 校验 `PROFILE_NAME_RE`
  - `src/profiles.js` —— `createProfile` 前置 `RESERVED_PROFILE_NAMES.includes(name)` 抛错

- 保留原因：
  - `desktop` —— DSH 官方硬编码的激活指针名（`ACTIVE_NAME`，无 env 覆盖），用户若新建同名会与激活机制撞车。
  - `default` —— 首次切换时把真实 `desktop` 存档成的名字，被占用后首切迁移会冲突。

- 测试：`test/settings.test.js` 增补 `PROFILE_NAME_RE` 正反例（`aaa` / `aaa-bb-c` / `my-modpack-1` / `a1-b2-c3` / `x` 合法；`Aaa` / `aaa_bb` / `aaa.bb` / `-aaa` / `aaa-` / `aaa--bb` / 中文等非法）与 `RESERVED_PROFILE_NAMES` 断言。

## 3. 图标

### 3.1 插件管理页图标 —— 已接好（未提交）

DSH 插件管理页的图标来自 `package.json` 顶层 `icon` 字段（相对路径的 SVG/PNG，≤256KB，转 base64 渲染）。本轮加了：

```jsonc
"icon": "icons/folder-zip-line.svg",
"files": ["src", "lib", "icons", "cordis.patch.yml"]
```

图标文件 `icons/folder-zip-line.svg`（用户提供）。

> ⚠️ 当前状态：`package.json` 改动 + `icons/` 目录**尚未提交**（见下方「提交状态」）。

### 3.2 设置面板左侧齿轮 —— 结论：插件侧无法换，维持原样

排查了 DSH 外壳源码，确认该导航图标**插件侧没有任何注入点**：

- 槽位契约 `ui-settings-general/src/client/shell-contract.ts` 的 `SettingsSectionRow` 只有 `{ id, order, label }` 三个字段，**没有 icon**。
- 行投影 `ui-settings-general/src/client/index.ts`（136–142 行）只挑 `id` / `order` / `label`，注册时传其它信息会被丢弃。
- 图标由 `ui-settings-general/src/client/SettingsRoot.tsx` 的 `navIcon(id)` 硬编码：仅 `account` / `models` / `agent-presets` / `plugins` / `archived-sessions` 五个内置 id 有专属图标，其余一律齿轮兜底。本插件 section id 为 `dspack`，必然吃到齿轮。

**要换，唯一路径是改 DSH 外壳的 `navIcon()`**（如加 `if (id === 'dspack') return <IconFolderCloseMedium …/>`），但那样就破了「零官方源码改动」。经与用户确认，最终决定**不改壳、齿轮维持原样**。
